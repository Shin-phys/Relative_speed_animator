# 相対運動ビューア（仮称）開発仕様書 v0.1

## 0. 概要

2物体の相対運動を、**3D一人称視点**と**2D俯瞰図**の2画面で観察するWebアプリ。 3Dで「観測者に乗ったときの見え方」を体験し、2Dで「速度ベクトルの引き算（v_BA = v_B − v_A）」と作図で確かめる。この往復を授業の流れとして組み込む。

- 対象：高校物理基礎（相対速度）
- 利用場面：対面授業での提示・生徒の個別操作、通信制課程での自習
- 基本方針：インストール不要、ブラウザ内処理のみ、PC・タブレット・スマホで動作

## 1. 技術構成

単一HTMLではなく、関心を分離したモジュール構成で開発する。シナリオの追加や表示方法の変更が今後も見込まれるため、機能ごとにファイルを分け、改訂の影響範囲を狭くする。

| 項目         | 内容                                                                                                     |
|--------------|----------------------------------------------------------------------------------------------------------|
| 開発環境     | Vite + TypeScript                                                                                        |
| UI・状態管理 | React（設定パネル・時間制御バーなど）                                                                    |
| 3D描画       | three.js                                                                                                 |
| 2D描画       | Canvas 2D API（Reactからは ref 経由で命令的に描画）                                                      |
| 物理計算     | 等速直線運動の解析解（数値積分は使わない）                                                               |
| ビルド出力   | `vite build` で `dist/` に静的ファイル一式を出力し、そのままホスティングする（出力が複数ファイルでよい） |
| 外部通信     | なし（three.js等もバンドルに含め、実行時のCDN依存をなくす）                                              |

時刻 t を与えると、全物体の位置を式から直接求める。この方式にすると、スライダーでの任意時刻への移動、逆方向のコマ送り、最接近時刻へのジャンプが誤差なく実現できる。

### ディレクトリ構成（案）

    src/
      physics/       … 相対運動の計算（位置・最接近・衝突判定）。UIやレンダラに依存しない純粋な関数群
      scenarios/     … シナリオのプリセット定義（並走・すれ違い・交差・コリジョンコース）
      state/         … 時刻・再生状態・シナリオ設定・表示設定の共有ストア
      scene3d/       … three.jsのシーン構築、カメラ制御、背景（格子・電柱・遠景）
      scene2d/       … Canvas 2D描画（ベクトル、相対軌跡、距離-時間グラフ）
      components/    … 条件設定パネル、時間制御バー、方位インジケータなどのReact UI
      hooks/         … 3D/2Dキャンバスの初期化・再描画をReactに接続するフック
      types/         … 共有の型定義（シナリオ、状態、ベクトルなど）
      main.tsx

- `physics/` を他から独立させておくことで、受け入れ確認項目（9章）の内容をテストしやすくする。
- シナリオを追加する際は `scenarios/` にプリセットを足すだけで済むようにする。

## 2. 運用フローと画面構成

### 2.1 基本フロー

1.  **条件設定**：専用パネルでシナリオと数値を設定する。このパネルには、速度ベクトルの合成や相対軌跡を表示しない。
2.  **再生（片側のみ表示）**：既定では3D画面だけを表示し、2D画面は隠す。
3.  **予想・観察**：生徒が見え方を観察し、言葉にする。
4.  **もう一方を開く**：「俯瞰図を開く」ボタンで2D画面を表示し、作図で確かめる。

先に表示する画面（3D／2D）は、教員が設定で切り替えられるようにする。

### 2.2 レイアウト

- **PC・タブレット（横長）**
  - 上段：2画面を左右に並べる（左：3D、右：2D）。隠した側には「開く」ボタンだけを置いたプレースホルダを表示する。
  - 下段：時間制御バー（両画面共通）。
  - 条件設定と表示設定は、開閉できるサイドパネルにまとめる。
- **スマホ（縦長）**
  - 縦に並べ、3D画面を上に置く。
  - 時間制御バーは画面下部に固定する。
- ボタンはタブレットで押しやすい大きさにする（目安：一辺44px以上）。

## 3. 物理モデル

### 3.1 座標系

- 地面系の水平面を (x, y) とする。俯瞰図では x を右、y を上に取る。
- three.js 内では y 軸が鉛直上向きなので、地面系 (x, y) を three.js の (x, −z) に対応させる。
- 単位は m、m/s を基本とする（表示単位は未決事項を参照）。

### 3.2 運動

- 位置：r_A(t) = r_A0 + v_A t、r_B(t) = r_B0 + v_B t
- 相対位置：r_BA(t) = r_B(t) − r_A(t)
- 相対速度：v_BA = v_B − v_A（一定）

### 3.3 最接近と衝突判定

- 最接近時刻：t\* = −(r_BA0 · v_BA) / \|v_BA\|²
  - t\* を再生区間 \[0, T\] に収める。
  - \|v_BA\| = 0 のとき（並走で同速の場合）は距離が一定なので、t\* を定義しない。
- 最接近距離：d_min = \|r_BA(t\*)\|
- 衝突判定：d_min \< R_A + R_B（R は各物体の当たり判定半径）
- 衝突した場合は、衝突時刻で両物体を停止させ、簡易的なエフェクトを表示する。

## 4. シナリオ（初版）

| シナリオ         | 設定パラメータ                                     | 観察のねらい                                                         |
|------------------|----------------------------------------------------|----------------------------------------------------------------------|
| 並走             | v_A, v_B（同じ向き）, 横方向の間隔                 | 速度差だけ前後に動いて見える／同速なら静止して見える                 |
| すれ違い         | v_A, v_B（逆向き）, 横方向の間隔                   | 速さの和で近づき、遠ざかる                                           |
| 交差             | v_A, v_B, 交差角 θ（0〜180°、任意）, 初期位置      | 斜め方向から横切って見える                                           |
| コリジョンコース | v_A, v_B, 交差角 θ, 交点, タイミングのずれ Δt      | 方位が変わらず近づくと衝突する（CBDR）                               |
| 流れの中の運動   | v_A（媒質の流れ）, v_B_相対（媒質に対するBの速度） | x方向とy方向の速度成分を合成すると斜め方向に進むことが直感的にわかる |

- 各シナリオにプリセット（典型値）を用意し、数値入力で自由に変更できるようにする。
- **コリジョンコース**
  - 交点と到達時刻が一致するように、初期位置を自動で計算する。
  - Δt（到達時刻のずれ）を 0 にすると衝突し、0 以外にすると衝突しない。
  - 「衝突する／しない」をワンタッチで切り替えて比較できるようにする。
- **流れの中の運動**（川を渡る船・動く歩道の上を歩く人などが典型例）
  - ねらいは、v_A（媒質）と v_B_相対（媒質に対する物体の速度）を合成すると v_B（地面から見た速度）が斜め方向になる、という体感に絞る。
  - 計算は既存の関係式 v_B = v_A + v_B_相対 をそのまま使う（v_BA = v_B − v_A の書き換えなので、物理計算部分の追加実装は不要）。
  - 3D側の背景は、格子ではなく川面や風の流れなど、媒質が流れている表現にする。
  - **「最短時間で渡る角度」「最短距離で渡る角度」を当てさせる狙い撃ち問題は扱わない。** 観察と作図による確認にとどめ、目標地点への到達を問う出題形式は第2段階に回す（10章参照）。
  - プリセットは、斜め方向（任意角度）だけでなく、v_A と v_B_相対 が同一直線上になる場合（θ = 0° または 180°）も用意し、段階的に見せる。
    - **順方向**（θ = 0°）：v_B = v_A + v_B_相対。地面から見ると加速して見える。
    - **逆方向**（θ = 180°）：v_B = v_A − v_B_相対。地面から見ると減速して見える。\|v_B_相対\| \> \|v_A\| の場合は、地面から見た運動の向きそのものが反転する（例：流れに逆らって強く進むと、結果として上流側へ進む）。
    - この1次元の場合を先に確認してから任意角度（斜め方向）に進むと、「合成によって速さだけでなく向きも変わりうる」という点が、斜め方向の場合の理解にもつながる。
- 条件設定パネルには、初期位置と進行方向を示す簡易図だけを表示する（問題文の図に相当する情報まで）。

## 5. 3D画面

### 5.1 観測者

- 観測者は「Aに乗る」「Bに乗る」「地面に立つ」から選ぶ。
  - 地面の場合は、位置を指定する固定カメラとする。
- 観測者を切り替えると、2D画面の基準系も連動して切り替わる（6.1参照）。

### 5.2 カメラ

- カメラは観測者の位置に置き、目線の高さは観測者の形状に合わせる。
- **向きは観測者の速度方向を基準に固定し、相手を追いかけて回転させない。** 方位の変化を読み取れるようにするため。
- 視点は「前方」「後方」「左側方」「右側方」の4方向から、ボタンで切り替える。
- 視野角は水平 65° 程度とする（three.js の垂直視野角は、画面のアスペクト比から換算する）。
- 観測者の速さが 0 の場合は、地面系の +x 方向を「前方」とする。

### 5.3 背景（自分が動いている感覚の演出）

- 地面に格子を描く。
- 電柱または木を等間隔に置き、観測者の後方へ流れていくように見せる。
- 遠景に山並みなどを置く。距離が遠いので方位の目印として機能する。
- 背景は必要な範囲だけ繰り返し生成し、端末の負荷を抑える。

### 5.4 物体

- 電車・船などの簡易形状で描く。
- A・Bは色だけで区別せず、形状またはラベルでも識別できるようにする。

### 5.5 方位インジケータ

- 画面上端に、相手の方位（観測者の進行方向を 0° とした角度）をマーカーで表示する。
- マーカーの過去の位置を薄く残し、方位が変化しているかどうかが見えるようにする。
- 相手が視野の外にいるときは、画面端に方向を示す矢印を出す。

### 5.6 ヒントの非表示

- 3D画面では、既定でベクトル・軌跡・数値を表示しない。
- 教員設定で、距離や方位角の数値表示をオンにできる。

## 6. 2D俯瞰画面

### 6.1 基準系

以下の3つをトグルで切り替える。3D画面の観測者と連動させる。

- **地面系**：両物体が v_A、v_B で動き、格子は静止する。
- **A系**：Aを中央に固定し、格子が −v_A で流れ、Bが v_BA で動く。
- **B系**：Bを中央に固定し、Aが v_AB（= −v_BA）で動く。

### 6.2 ベクトル表示（段階表示）

「次へ」ボタンで、以下の順に表示を進める。

1.  v_A と v_B を表示する。
2.  −v_A を表示する。
3.  合成して v_BA を表示する。

作図方法は2通りから選べるようにする。

- **始点そろえ型**：v_A と v_B の始点をそろえ、v_A の先端から v_B の先端へ矢印を引く。
- **つなぎ型**：v_B の先端に −v_A をつなぐ。

ベクトルの長さと表示スケールは、設定で調整できるようにする。

### 6.3 相対軌跡と最接近

- 観測者系では、相手の相対軌跡（直線）を点線で表示する。
- 観測者から相対軌跡へ垂線を下ろし、d_min を表示する。
- 相対軌跡が観測者の当たり判定円と交わる場合は、衝突コースであることを表示する。
- 各項目の表示／非表示は個別に切り替えられるようにする。

### 6.4 その他の表示

- 3Dカメラの視野を扇形で重ねて表示し、3D画面の視点切替と連動させる。
- 軌跡の履歴を一定時間ごとの点で残すストロボ表示を、オン／オフできるようにする。
- ズームとパン（ピンチ操作・ホイール操作に対応）ができるようにする。

### 6.5 距離−時間グラフ

- 2D画面の隅に小窓で表示する。3D画面だけを表示している間は隠す。
- 横軸を時刻、縦軸を相対距離とし、現在時刻の縦線と最接近点（谷）のマーカーを描く。

## 8. 教員向け設定

- 先に表示する画面（3D／2D）を選べるようにする。
- 3D画面のヒント（数値表示）をオン／オフできるようにする。
- 2D画面のベクトル段階表示の初期段階を選べるようにする。
- 可能であれば、シナリオの設定をURLパラメータに含めて共有できるようにする（配布用）。

**UI文言の方針**：ラベルやガイド文で結論を先に示さない。道具の説明と操作の指示だけを書く。

- 悪い例：「相手は静止して見える」「衝突コース：方位が一定」
- 良い例：「Aから見ると？」「相手の方向はどう変わる？」

## 9. 受け入れ確認項目

以下をすべて満たすことを確認する。

- 観測者系の相対軌跡が直線になる。
- A系とB系で、相手の動きがちょうど逆向きになる。
- 並走で同速のとき、3D画面で相手が静止して見える。
- コリジョンコース（Δt = 0）で、方位インジケータが一定のまま衝突する。
- Δt ≠ 0 のとき、方位が少しずつ変化し、衝突しない。
- 「最接近へジャンプ」の時刻と、距離グラフの谷が一致する。
- 流れの中の運動で、v_A と v_B_相対 を合成した v_B が、地面から見て斜め方向になっている。
- 流れの中の運動（逆方向）で、\|v_B_相対\| \> \|v_A\| のとき、地面から見た運動の向きが反転する。
- 3D・2D・グラフの時刻が常に一致している（コマ送り・スライダー操作時を含む）。
- 片側を隠した状態でも、もう片側が正常に動作する。
- 一般的なタブレット・スマホで、実用的な速度で動作する。

## 10. 第2段階（初版の対象外）

- **モンキーハンティング**
  - 鉛直面内の側面図モードを追加する。
  - 重力 g を導入する（相対加速度が 0 になることを示す）。
  - 弾の視点を用意する（背景が加速して流れる見え方）。
- **電車から見た雨**：鉛直方向の成分を含む相対速度を扱う。
- **合成速度の最短経路問題**：川を渡る船などで、最短時間または最短距離となる角度を当てさせる出題形式。目標地点の設定、角度と到達点の連動表示、経路長の比較表示などが必要になるため、4章の「流れの中の運動」（観察版）とは別に設計する。
- **等加速度成分を含む合成運動（放物線）**：一方の成分が等速、もう一方が等加速度のとき、軌道が放物線になることを示す発展モデル。難関大学志望者向け。位置は x(t) = x0 + v_x t、y(t) = y0 + v_y0 t + (1/2) a t² と解析解のまま扱えるため、物理計算部分の拡張は小さい。ただし2物体の相対運動ではなく「1物体の2成分の合成」を示すモードになるため、UI・表示は別立てで設計する。落下比較アプリ（斜方投射）との関連が深く、資産を流用できる可能性がある。
- **3D疑似パノラマ**：前方と左右を3枚並べて表示する。
- **加速度運動**：非慣性系・慣性力との関係を扱う（別単元として設計する）。
